# 심사 모듈 — 모의 피어리뷰 & 퇴고 루프

양식·규율: `corpus/_review-template.md`. 심사자: `peer-reviewer` 에이전트. 절대 원칙 상속: **지적은 본문 verbatim 정박**(기계 대조 — 미정박은 질문 격하), **문헌 제안은 서지 단정 금지**. 모의 심사는 실제 심사가 아니다 — 산출물에 그렇게 표시한다.

## 시작할 때 두 가지를 정한다

1. **모드**: **A** 자기 논문(집필 파이프라인 산출물) / **B** 타인 원고 심사 보조 — ⚠ 학술지의 AI 사용 규정·비밀유지 의무를 먼저 확인한다. 규정이 AI 사용을 막으면 진행하지 않는다. AI는 심사 메모 초안까지만, 판정·심사문은 저자가 직접 쓴다 / **C** 외부 초고 발전 루프 — `_workspace/{이름}/`에 원고 md + `_meta.md`만 두고 돌림(화이트리스트가 없으면 항목 5는 "검증 불가" 표시만).
2. **심사 시점**: `draft`(초고 — 논지·구조 중심) / `final`(투고 직전 — 전 항목 엄격). 저자가 정한다.

## 절차 (회차 r{n})

1. **원고 준비**: docx면 추출 전 **변경추적 검사 필수**(<w:ins>/<w:del> — 미수락분이 있으면 '수락' 규칙으로 정본 추출, 이력은 `_provenance.md`에 기록).
2. **심사자 3인 병렬**: ①전공 사료·고증(분야 설정과 0단계 논평자 관점 흡수) ②방법론·이론 ③편집위원(투고지 규정). 8항목 5점 척도 + 번호 지적(주요/경미/질문) + 검증한 것(통과 목록) + 4등급 판정. **입력은 블라인드**: 산출물(원고·화이트리스트·verify 출력·[재심]직전 답변서)과 증거층만 주고, 집필 대화·`_authorial_foundation.md`·`_problematization.md`·배열판·윤문 리포트는 주지 않는다 — 저자의 서사에 정박한 심사는 결함을 통과시킨다.
3. **정박 기계 대조**: 모든 지적의 quote를 원고에 대조(공백 정규화+강정규화). 미정박 = 질문 격하 표시.
4. **합본**: `10_review_r{n}.md`.
5. **저자 게이트(triage)**: 지적별 수용/부분수용/반박 → `10_response_r{n}.md`(답변서 — 실전 예행).
6. **수정**: 수용분 반영(집필·윤문 모듈 활용) → `python tools/verify.py` 재통과.
7. **재심 여부·루프 종료는 저자가 선언**한다.

## 한계

모의 심사는 같은 모델 계열이 쓴 원고를 같은 계열이 읽는 구조라 맹점이 겹칠 수 있다. 역할 분리(관점 3개)는 실제 독립 심사가 아니다 — 투고 전 동료 연구자의 실제 검토를 대신하지 않는다.
