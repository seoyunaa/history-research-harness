# 모의 심사 양식 (10단계 — 투고 전 동료 심사 시뮬레이션)

> 초고(04~08)를 완성한 뒤 `_workspace/{논문}/10_review_r{n}.md`(심사표)와 `10_response_r{n}.md`(저자 답변서)로 쓴다. **심사 → 답변·수정 → 재심** 루프를 저자가 종료할 때까지 반복한다(r1, r2, …).
>
> **심사자 절대 원칙(상속)**:
> ① **본문 정박** — 모든 지적은 **본문 실제 구절에 정박**한다(절·문단 + 원문 인용 조각). 지적을 지어내지 않는다. 정박하지 못하는 인상 비평은 "질문"으로 격하해 표시한다.
> ② **문헌 제안 단정 금지** — "이런 연구가 있을 것"은 `[제안 — 저자 실재 확인 요]`로 표시하고 서지를 창작하지 않는다. 저자가 도서관(검색 위계 순서)에서 확인한 뒤에만 반영한다.
> ③ **갭 마커는 알려진 작업분** — `[GAP:...]` 마커의 존재 자체를 흠잡지 말고 *게재 전 소진 대상*으로만 지적한다.
> ④ **블라인드** — 심사자는 산출물(초고·화이트리스트·verify 출력)과 증거층(카드·CSV·매니페스트·처리 이력)만 본다(재심 때 직전 답변서는 예외 — 실제 심사 관행). 집필 대화와 저자 의도 메모(`_authorial_foundation.md`·`_problematization.md`·`_카드배열판_vN.md`)는 입력이 아니다. 저자의 서사를 보면 그 논리에 기대어 결함을 통과시키게 된다. 저자의 확신은 증거가 아니다.
> ⑤ **수치 역추적** — 수량 주장(N건·N%·비율)은 증거층으로 역추적하고, 어느 증거에도 없는 수치는 날조로 추정해 지적한다(verify.py의 「수치 역추적」 GC가 기계 근거 — 04~08·투고 계열 *draft* 파일만 스캔).
>
> ④⑤는 AI가 심사자인 모드 A·C에 적용되며, 모드별 강등은 해당 모드 절을 따른다.

## 심사표 (심사자 1인당 1부)

**논문**: {제목} · **심사 회차**: r{n} · **원고 단계**: draft / final · **심사자 관점**: {전공 사료·고증 / 방법론·이론 / 편집위원(형식·완결)}

### 1. 항목별 평가 (5점 척도: 5 매우 우수 · 4 우수 · 3 보통 · 2 미흡 · 1 매우 미흡)

| # | 항목 | 점수 | 촌평(한 줄) |
|---|---|---|---|
| 1 | 학술지 논문으로서의 적합성 | | (투고지 성격·분량·형식 부합) |
| 2 | 연구 방법의 적절성 | | (사료 운용·논증 방식) |
| 3 | 내용의 완결성 | | (장 사이의 결속·미결 부분) |
| 4 | 논문 작성의 성실성 | | (각주 밀도·표기 일관·오탈자) |
| 5 | 참고문헌 인용의 정확성 | | (verify.py·각주 감사 결과 반영) |
| 6 | 논문 주제의 창의성 | | (선행연구 대비 새로움) |
| 7 | 연구 결과의 학문적 기여도(기대 효과) | | (분야에 무엇을 더하나) |
| 8 | 논문 초록의 적합성 | | (초록↔본문 정합·주제어) |

### 2. 지적사항 (번호 부여 — 답변서가 이 번호로 응답)

각 지적: **[R{심사자}-{번호}] (주요/경미) 항목# · 위치(장·절) · 본문 정박 인용("…") · 문제 · 수정 제안**

- 주요(major) = 게재 판정을 좌우 / 경미(minor) = 표현·형식.
- 문헌 제안이 포함되면 끝에 `[제안 — 저자 실재 확인 요]`.
- 사료 비판 관점의 점검 예: 1차/2차 구분이 섞이지 않았는가, 연대 환산 근거가 밝혀졌는가(`[GAP:연대]` 잔존 여부), 확신도 표현이 증거 강도와 맞는가, `[AI잠정]` 표시가 남은 채 단정한 곳이 없는가.

### 3. 검증한 것 (통과 목록)

지적 못지않게 *대조해서 통과시킨 것*을 적는다: 인용의 원문 일치 표본, 수치 결속 확인분, 확인한 각주 범위 등. **심사가 덮은 범위와 보지 않은 범위를 경계 짓는다** — 통과 목록이 빈 심사표는 전수 인상 비평과 구별되지 않는다.

### 4. 종합 판정

**게재 가 / 수정 후 게재 / 수정 후 재심 / 게재 불가** + 판정 사유 한 문단.

## 답변서 (저자, `10_response_r{n}.md`)

지적 번호별로 **수용 / 부분 수용 / 반박** 중 하나 + 근거:

- **수용** → 어느 파일 어느 절을 어떻게 고쳤는지(수정은 04~08 파일에 반영, verify.py 재통과 확인).
- **부분 수용** → 수용 범위와 이유.
- **반박** → 사료·논증 근거로 응답한다(실제 심사 답변서의 예행연습이다). 반박도 화이트리스트 안에서 한다.

수정을 마친 뒤 재심(r{n+1}) 여부는 저자가 정한다. **"충분/그만"은 저자가 선언한다.**

> 심사자 3인 표준 구성: ① 전공 사료·고증(0단계에서 파악한 실제 논평자 관점 반영 — 예: 해당 사료군의 전공자) ② 방법론·이론(논문의 이론 틀 분야) ③ 편집위원(형식·완결·초록·가독). 관점이 겹치면 줄여도 된다.

## 심사 시점 (강도 보정)

심사 전에 **원고 단계**를 지정한다. 초고를 투고 직전 기준으로 재단하면 판정이 부당하게 박해진다.

- **draft(초고)**: 논지·구조·논증의 강도만 판정에 반영한다. 참고문헌 미정비·`[GAP]`·서지 빈칸·표기 불일치 같은 *알려진 작업분*은 지적하되 **"작업 목록"으로 분리**하고 점수·판정에서 감점하지 않는다(항목 3·4·5는 "작업분 제외 시" 기준으로 채점). 판정도 "논지 기준"임을 밝힌다.
- **final(투고 직전)**: 전 항목을 엄격하게 — 실제 심사자가 볼 상태 그대로 재단한다.

## 세 가지 모드 (사용처별 규율)

### 모드 A — 자기 논문 10단계 (기본)
위 그대로. 9단계 파이프라인의 산출물을 심사하고, 화이트리스트·verify.py가 항목 5의 기계 근거가 된다.

### 모드 B — 타인 원고 심사 보조 (저자가 실제 심사자일 때)
**역할이 뒤집힌다. AI는 심사자가 아니라 심사자의 보조 눈이다.** 산출물은 제출용 심사문이 아니라 **심사 메모 초안**(`[AI잠정]`)이고, 최종 심사문은 저자가 자기 판단·자기 문장으로 쓴다(CLAUDE.md 상위 헌장 4기준 중 ④ — 판단은 위임할 수 없다).

- ⚠ **비밀유지 먼저**: 심사 원고는 학술지에 대한 비밀유지 의무 대상이다. **해당 학술지의 AI 사용 규정을 먼저 확인**하고, 불허하거나 불분명하면 원고 전문을 넣지 않는다(항목 구조·논증 흐름을 저자가 요약해 넣는 축소 모드로). 사용했다면 심사 과정 공개 규범(4기준 중 ③)도 저자가 판단한다.
- AI 보조가 실제로 잘하는 것: **원고 내 정합성**(본문↔초록, 시기·표기 일관, 논리 긴장 — 전부 원고에 정박한 지적), **인용 실재 대조**(각주 문헌이 저자 도서관에서 검색 위계 순서로 확인되는가), **심사표 8항목 체크리스트 순회**.
- AI가 하면 안 되는 것: 종합 판정 결정, 심사문 문장 작성 대행, **누락 문헌의 서지 단정**(모드 A와 같다 — 제안까지만).
- **원칙 ④⑤의 모드 B 경계**: ④는 해당 없음 — AI는 심사자가 아니라 보조 눈이고, 입력 범위는 저자와 학술지 규정이 정한다. ⑤는 "역추적 불가 — 표시"까지만: 증거층에 접근할 수 없는 타인 원고의 수치를 날조로 추정하지 않는다.

### 모드 C — 외부 초고 발전 루프 (파이프라인 밖 원고)
9단계를 거치지 않은 초고(과거 원고·다른 학술지 투고본·docx)를 심사 → 수정 루프에 태운다.

- `_workspace/{이름}/`을 만들고 원고(md 변환)와 간단한 `_meta.md`(투고 대상·상태)만 둔다. 화이트리스트가 없으므로 **항목 5(인용 정확성)는 "검증 불가 — 표시만"으로 강등**하고, 심사자는 각주 실재를 단정하지 않는다(저자 도서관 대조는 가능). **수치 역추적(원칙 ⑤)도 같다** — 증거층이 없으면 "역추적 불가 — 표시만"으로 강등하고 날조로 추정하지 않는다(verify.py의 수치 역추적은 04~08·투고 계열 *draft* 명명 파일만 스캔하므로 외부 원고에는 돌지 않는다).
- 루프는 모드 A와 같다(심사 → triage 답변서 → 수정 → 재심). 원고가 발전해 정식 투고 궤도에 오르면 2단계(화이트리스트 소급 구축)로 승급할 수 있다.
